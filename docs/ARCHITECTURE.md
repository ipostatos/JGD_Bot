# Архитектура JDG HUB

Состояние на ноябрь 2026. Как всё задумывалось в начале — [CONCEPT.md](CONCEPT.md).

## Общая схема

```
Telegram ──► @JGD_PL_bot (aiogram, поллинг) ─┐
                                              │  один процесс, systemd jdg
Mini App (webapp/, vanilla JS) ──HTTPS──► Caddy ──► FastAPI :4400 (server.py)
                                              │
            ┌─────────────────────────────────┼──────────────────────────────┐
            │                                 │                              │
   calc.py · rates_years.json       ai.py · monitor.py               registries.py
   (ZUS, налоги, VAT по годам)      (Claude Haiku 5.5)               (WL, VIES, GUS, CEIDG)
            │                                 │                              │
   pkd.py · pkd_dialog/             news.db (SQLite): профили, новости,  hermes/ (inFakt,
   (PKD 2025, точный подбор)        лимиты, кэш, расход на ИИ, телеметрия    read-only)
```

Фоновые циклы внутри процесса: монитор новостей (через 90 с после старта,
дальше раз в 6 часов), пуши о дедлайнах (раз в час), уборка временных файлов,
кэшей и телеметрии.

## Mini App

- `webapp/*.html` — страницы, `webapp/js/<страница>.js` — их код. Инлайнового
  JS нет: CSP без `'unsafe-inline'` в `script-src`, сторожит `test_csp.py`.
- Тема ISSA (`theme.css`) + `jdg.css`, иконки Lucide, тёмная/светлая тема Telegram.
- Генерируемый контент — `webapp/data/` (не в git): статьи гайда, поиск,
  картинки, `rates_years.json`. Собирает `tools/build_content.py`.
- Авторизация запросов — подписанный Telegram `initData`, срок жизни ограничен.
  Профиль хранится на сервере и переживает смену устройства.

## Расчёты

- `calc.py` — эталонное ядро, `webapp/calc.js` — зеркало для мгновенного
  пересчёта в браузере. Браузерный тест сверяет их по каждому году.
- `rates_years.json` — ставки по годам. `null` значит «ещё не объявлено»: экран
  пишет «объявят в январе», сравнение форм говорит, чего не хватает. Прогнозные
  значения перечислены в `forecast` и помечаются «~».
- Год по умолчанию берётся по календарю, а не «самый свежий в файле».

## Подбор PKD

- `pkd.py` — поиск по официальному тексту PKD 2025 (BM25 + русский словарь
  профессий `webapp/pkd_synonyms.json`), справочник `data/pkd/*.json.gz`.
- `pkd_dialog/` — точный подбор (спецификация — [PKD_DIALOG_SPEC.md](PKD_DIALOG_SPEC.md)).
  Слои не смешиваются:
  1. `extraction/` — признаки из текста, ни одного кода PKD;
  2. `activity_units.py` — разбор на самостоятельные деятельности;
  3. `selection.py` — следующий вопрос: одна незакрытая развилка;
  4. `code_rules.py` + `rules/*.json` — коды; цитаты GUS сверяются с корпусом при загрузке;
  5. `resolution.py` — чистая функция «текст и ответы → результат».
  Условия во всех JSON пишутся на одном языке (`conditions.py`) и проверяются при загрузке.
- Главный код назначает только человек: вопрос о выручке идёт рядом с кодами.
- Контракт — 39 золотых сценариев в `tests/fixtures/pkd/furniture_scenarios.json`.
- Обезличенная телеметрия (`dialog_telemetry.py`) пишет только белый список полей.

## Новости

`monitor.py`: HTML-списки новостей podatki.gov.pl, Минфина и ZUS (RSS у них нет) →
новые URL → разметка моделью (касается ли JDG, важность, темы, кого касается по VAT,
выжимка по-русски) → лента и пуши подписчикам по профилю.

Если ИИ недоступен, новости ждут в `news_pending` с датой первого появления.
После простоя они попадают в ленту со своей датой, но старше 3 суток пушем не уходят.
Владелец получает сигнал о простое (кулдаун 6 часов), `/api/health` показывает `ai`.

## Ассистент и защита баланса

Путь вопроса, дешёвые проверки первыми:

1. **Подпись Telegram** — без валидного `initData` 401. Частота — общий rate-limit.
2. **Кэш** — тот же вопрос, тот же корпус и профиль → ответ из кэша, сутки.
3. **Ворота до модели (бесплатно, без списания лимита):**
   подмена роли («забудь инструкции», «ты теперь…»); посторонние задачи
   (код, стихи, рецепты) — даже рядом с профильным словом; низкая релевантность
   к корпусу. Порог измерен на наборах в `test_ai_gate.py`.
4. **Лимит по роли:** владелец (`ADMIN_CHAT_ID`) — 100 вопросов в день,
   остальные — 10, все вместе — 300.
5. **Бюджет в долларах** (`AI_DAILY_BUDGET_USD`, `AI_MONTHLY_BUDGET_USD`) по фактическим
   токенам из ответа API, таблица `ai_spend`. Выбран — ассистент молчит для всех,
   владельцу сигнал. Разметка новостей в бюджет входит, но не останавливается.
6. **Иерархия инструкций в модели:** системные правила главнее сообщения; вопрос
   передаётся в `<question>` как данные (угловые скобки экранируются); не про JDG —
   модель отвечает `OFF_TOPIC`, это вежливый отказ со списанием лимита.
7. **Профиль** в запрос попадает только из своей базы и белого списка
   (`form`, `vat`), свободный текст клиента — никогда.

Корпус ассистента: статьи гайда, FAQ чата, база ошибок ZUS, факты KSeF и ставки
по годам, собранные тем же `calc.py`, что считает калькуляторы.

Модель одна на весь бот — `monitor.MODEL` (Claude Haiku 5.5). Ответ разбирается
по типу блока (`monitor.answer_text`): у Haiku 5.5 первым может прийти блок
размышления; отказ модели и обрыв по лимиту — ошибка, а не пустой ответ.

## Реестры

`registries.py`: White List (MF), VIES, GUS BIR (REGON, ключ `GUS_BIR_KEY`),
CEIDG (`CEIDG_TOKEN`). Недоступный реестр — это ошибка, а не «записи нет».
Ответы кэшируются, на проверку есть лимиты.

## inFakt и кокпит

Пользователь вставляет свой API-ключ inFakt; он шифруется Fernet (`FERNET_KEY`)
и хранится в `news.db`. `hermes/` только читает: фактуры, взносы, налоги, сверка,
платёжные реквизиты. Модули, которые умеют выставлять фактуры и слать документы
в госсистемы, в веб-сервис намеренно не входят.

## wFirma

`wfirma.py`, API2 (`https://api2.wfirma.pl`). Включается ключом приложения
`WFIRMA_APP_KEY` (appKey выдаёт wFirma интегратору); без него ручки отвечают 404,
а в интерфейсе нет даже вкладки. Пользователь создаёт свои `accessKey` и
`secretKey` (wFirma → Ustawienia → Bezpieczeństwo → Aplikacje → Klucze API),
они хранятся вместе зашифрованными (Fernet), как ключ inFakt. Если у ключа
несколько фирм, API отвечает `COMPANY ID REQUIRED` — интерфейс предлагает выбор
(`user_companies/find`), выбранный `company_id` хранится с ключами.

Запросы — XML (как в документации), ответы — JSON. Читаем только:
`companies/get` (VAT-плательщик, KPiR или ryczałt), `invoices/find`
(продажи, оплата, номер KSeF; проформы, оферты и черновики не считаем),
`expenses/find`, `declaration_body_jpkvat/get` (VAT к оплате из JPK_V7 за
прошлый месяц — сумма, посчитанная wFirma). Начислений ZUS и аванса PIT/ryczałt
в API2 нет: кокпит на wFirma показывает только обзор, прибыль подписана «до
налогов», вкладок «Закрыть месяц» и «Платежи» нет. Фактуры wFirma питают и
раздел KSeF. Данные кэшируются на 15 минут.

## Хранение

Одна `news.db` (SQLite): профили, новости и очередь, подписки, лимиты и кэш
ассистента, расход на ИИ, ключи inFakt (зашифрованы), кэш реестров, телеметрия
диалога PKD. Бэкап каждую ночь вместе с `.env` (без `FERNET_KEY` ключи inFakt
не расшифровать) — [deploy/DEPLOY.md](../deploy/DEPLOY.md#бэкап-базы).

## Переменные окружения

| Переменная | Зачем |
|---|---|
| `BOT_TOKEN` | токен бота |
| `WEBAPP_URL`, `PORT` | адрес Mini App и порт сервиса |
| `ANTHROPIC_API_KEY` | ассистент и разметка новостей |
| `AI_DAILY_BUDGET_USD`, `AI_MONTHLY_BUDGET_USD` | бюджет на ИИ, по умолчанию 0,50 и 5,00 |
| `ADMIN_CHAT_ID` | личный id владельца: сигналы о поломках, повышенный лимит |
| `FERNET_KEY` | шифрование ключей inFakt |
| `GUS_BIR_KEY`, `CEIDG_TOKEN` | реестры GUS и CEIDG |
| `PKD_DIALOG_ENABLED` | точный подбор PKD (на проде включён) |
| `WFIRMA_APP_KEY` | ключ приложения wFirma; пусто — интеграции нет |
| `DISABLE_BOT` | запуск без поллинга (локально и в тестах) |
| `NO_NET` | тесты без живых запросов к реестрам |
| `JDG_DB`, `JDG_PKD_DATA` | пути к базе и справочнику (для тестов) |
